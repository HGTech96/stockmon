## Interfaces

**`ui/src/api/types.js`** — one `@typedef` per contract shape, named to match
(`Meta`, `Suggestion`, `ChecklistItem`, `Warning`, `DashboardResponse`,
`DashboardStock`, `StockDetailResponse`, `Indicators`, `ChartData`, `Position`,
`ProfitTarget`, `PortfolioResponse`, `PortfolioPosition`, `TradeRequest`,
`TradeResponse`, `RefreshResponse`, `Settings`), imported via `@import` JSDoc
comments in each `api/*.js` file for editor autocomplete. No runtime validation
— types are documentation only, matching "plain JS, JSDoc for autocomplete."

**`ui/src/api/client.js`**
```js
const BASE_URL = "/api"; // Vite proxies to http://localhost:8000

async function request(path, options) {
  const res = await fetch(`${BASE_URL}${path}`, {
    headers: { "Content-Type": "application/json" },
    ...options,
  });
  const body = await res.json();
  if (!res.ok) throw new Error(body.error ?? "Request failed");
  return body;
}

export { request };
```

**`ui/src/api/stocks.js`**
```js
/** @returns {Promise<import('./types').DashboardResponse>} */
export function getStocks() { return request("/stocks"); }

/** @param {string} ticker
 *  @returns {Promise<import('./types').StockDetailResponse>} */
export function getStockDetail(ticker) { return request(`/stocks/${ticker}`); }
```
(`portfolio.js`, `trades.js`, `settings.js`, `refresh.js` follow the same
one-function-per-endpoint shape.)

**`ui/src/hooks/useDataRefresh.js`**
```js
/** Runs POST /api/refresh every REFRESH_INTERVAL_MS, then invalidates every
 *  query so pages refetch with fresh data. Mounted once in AppShell. */
const REFRESH_INTERVAL_MS = 15 * 60 * 1000; // 15 min — matches yfinance's own
  // up-to-15-min delay, so polling faster than the source data updates is wasted calls

function useDataRefresh() {
  const queryClient = useQueryClient();
  useEffect(() => {
    const id = setInterval(async () => {
      await postRefresh();
      queryClient.invalidateQueries();
    }, REFRESH_INTERVAL_MS);
    return () => clearInterval(id);
  }, [queryClient]);
}
```

## Implementation notes (deviations / additions beyond the plan)

- **Tailwind v4, not v3.** shadcn's current CLI (`shadcn@4.18.0`) expects v4's
  CSS-native setup (`@tailwindcss/vite` plugin, `@import "tailwindcss"`, a
  `@theme` block) rather than a `tailwind.config.js` + PostCSS pipeline; fighting
  the CLI toward v3 wasn't worth it. All design tokens live in a `@theme` block
  in `ui/src/index.css` instead of `tailwind.config.js` — same effect (tokens
  once, `bg-accent`/`text-ink-muted`/etc. utilities, no hardcoded hex in
  components), different file. There is no `tailwind.config.js`.
- **shadcn init pulled in more than tokens**: its Nova preset writes its own
  color system (oklch grays), a Geist font import, and dark-mode variables into
  `index.css`. Removed the Geist import (uninstalled
  `@fontsource-variable/geist`) and all dark-mode/`.dark` CSS — the product is
  light-only, matching the reference's `color-scheme:light`. Remapped shadcn's
  semantic tokens (`--primary`, `--background`, `--muted`, `--destructive`,
  `--border`, `--input`, `--ring`, etc.) onto our own design-token values
  instead of shadcn's defaults, so any primitive pulled in during Phase 5
  (Button, Dialog, ...) already matches the design without edits. Kept
  `tw-animate-css` and `shadcn/tailwind.css` (base-ui-driven component
  animation/utility infra) since Phase 5 will need them.
- **Deleted the auto-generated `button.jsx`.** shadcn's init drops a sample
  Button component even when no component is requested; removed it per the
  "init only, pull components in Phase 5 as needed" decision — nothing else
  referenced it.
- `jsconfig.json` added (not in the original file list) — required for the
  `@/*` import alias shadcn's CLI needs in a plain-JS (non-TypeScript) Vite
  project; `vite.config.js`'s `resolve.alias` provides the matching runtime
  alias.
- **Freshness data is per-page, not global.** Each GET response carries its
  own `meta` (per contract), so `AppShell` can't fetch it itself. Solved with
  React Router's `<Outlet context={{ setMeta }} />`: each page's `useQuery`
  reports its `data.meta` up via `useOutletContext()` in a `useEffect`, and
  `AppShell` renders `FreshnessBar`/the stale banner from that lifted state.
  `FreshnessBar` ended up as just the compact dot+timestamp (matching the
  reference's separate `.freshness` element) — the full-width stale banner is
  a second, sibling block in `AppShell` itself (matching the reference's
  separate `.global-banner` element), not a second thing `FreshnessBar`
  renders.
- Dropped the reference's hardcoded "Live prices unavailable." banner lead-in
  text — the contract's `staleMessage` is already a complete backend-authored
  sentence; prepending our own copy in front of it would invent wording the
  backend doesn't own.
- **Manual check caveat**: verified via `claude-in-chrome` that Dashboard,
  Portfolio, and Stock Detail (valid ticker) all fetch and render real data
  through the Vite proxy, with the nav and freshness dot/timestamp working
  correctly. The error-state branch (bad ticker) could *not* be observed
  rendering live in that automated tab — traced it to the tab lacking real
  OS-level focus (`document.visibilityState: "hidden"`), which is the exact
  condition TanStack Query's default retry logic pauses under
  (`focusManager.isFocused()` gates resuming a paused retry). This is
  confirmed a test-harness artifact, not an app bug: `request()` was verified
  directly to throw the contract's `{error}` message correctly, and the error
  JSX (`{error && <p>{error.message}</p>}`) is identical in shape to the
  success-path JSX that did render live data. In a normally focused browser
  tab this resolves in a few seconds via the standard retry/backoff.
